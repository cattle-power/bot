# 展示页设计流程

参考并改写自开源的 frontend-design 技能（github.com/anthropics/skills），精简成可直接交给编码代理的要求。

## 1. 先定主题
- 写清楚：页面展示什么、给谁看、主要任务是什么。缺信息就自己提一个具体方案。
- 视觉选择从主题本身的材质、行业和语境里来，不用通用模板。

## 2. 先写设计方案再写代码
- 配色：4–6 个带名字的 hex 色值。
- 字体：1–2 个刻意挑选的字体及用途，定好字号阶梯。
- 布局：一句话概念 + ASCII 线框图，写明对齐方式。
- 原则：这个页面独特在哪。
- 对照下面的「模板痕迹」自查，哪里像通用默认就改掉并说明理由。

## 3. 避免的模板痕迹（除非需求明确要）
- 米白底 + 衬线大标题 + 陶土色点缀；纯黑底 + 一个荧光绿点缀。
- 内容切成一样的圆角卡片、统一灰阴影、渐变铺底。
- 每个标题上方放全大写小标签、「A · B · C」式元信息、按钮后加箭头。
- 标题里只突出一个词；非序列内容用 01/02/03 编号。
- 每个区块都淡入上滑、每张卡片都有 hover 动效。

## 4. 克制
- 只在一处大胆：一个让人记住的主视觉（如首屏的 3D/互动），其余安静。
- 动效只用一个编排好的时刻（加载或滚动叙事）；响应用户操作的动效可以有。
- 质量底线：移动端自适应、键盘焦点可见、尊重 prefers-reduced-motion、对比度达标、每行不超过约 80 字符。
- 出门前照镜子，去掉一个装饰。

## 5. 文案
- 写用户看得懂的话，主动语态，按钮写清楚点了会发生什么。不堆宣传语。

## 6. 验收
- 本地跑起来，桌面和手机宽度各截一张图自评，再改一轮。
- 交付：可访问的预览链接（如 GitHub Pages）和截图。
